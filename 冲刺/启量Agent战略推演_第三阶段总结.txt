启量 Agent · PM 作战室推演 —— 第三阶段完整记录
================================================================

日期：2026-06-07
角色：风控审核员 / 小白用户（极度挑剔且愤怒）
项目：启量 Agent（TikTok 矩阵自营 · 内容电商 · 卖书品类）
核心议题：安全合规熔断机制 + 违禁词 RAG 闭环设计


================================================================
一、推演主题与核心问题
================================================================

本次推演围绕一个灾难场景展开：

  "Agent 翻译通道产生的文化/政治禁忌灾难" —— 如何用工程化手段
  实现"一键急停/熔断机制"和"人机协同审核机制"来防范和兜底？

推演过程中逐步从"一个违禁词 RAG 的想法"深挖到完整的
"信号采集 → LLM 推断 → 自动更新 → 分层拦截"五层闭环系统。


================================================================
二、推演路径回顾（逐轮攻防）
================================================================

【第 1 轮】灾难场景设定 —— 翻译通道是安全盲区
----------------------------------------------------------------
风控审核员切入角度：
  脚本话术 RAG 库中一条模板的英文翻译踩中了东南亚某国种族禁忌词。
  四阶段流水线全自动跑完——Phase 1 到 Phase 4，没有任何一道人工
  审核闸门拦截文本内容。45 个号在同一天不同时段分发该内容，
  TikTok 风控系统判定为"有组织恶意矩阵"，一键连坐，全部永封。

  现有人机协作闸门审的是画面好不好看、BGM 对不对，
  审的不是文本内容安不安全。翻译通道的输出 translated_script
  直接送进 TTS 和分发，全程没有任何人对翻译结果做安全审核。

核心拷问：
  "这个漏洞你怎么补？"

PM 方案：
  加一个东南亚违禁词的 RAG 库。


【第 2 轮】违禁词 RAG 的三层追问
----------------------------------------------------------------
风控审核员追问（攻击违禁词 RAG 方案）：

  问题 1 — 精确匹配 vs 语义匹配？
    精确匹配拦不住文化语境。"穆斯林"能拦，"清真"拦不拦？
    "Halal"是禁忌还是正常讨论，词库分不出来。
    语义匹配 → 每条过 LLM，405 条/天 Token 翻倍，毛利率击穿。

  问题 2 — 谁维护词库？
    东南亚 11 个国家、几十种语言。每次 TikTok 更新规范，
    谁手动加？运营忘了加，45 个号又死一轮。

  问题 3 — 挂在哪一层？
    中文原文没问题，是翻译通道把它变成了英文禁忌。
    违禁词 RAG 挂中文输入层拦不住，挂英文输出层回到成本问题。

PM 反思：
  "AI coding 正在变成水电煤级别的基建，不再是壁垒。
   真正的护城河是谁离热数据最近、谁更新得最快。"


【第 3 轮】热数据定义 —— 四类数据源的梳理
----------------------------------------------------------------
风控审核员引导思考：
  热数据的采集入口在哪？更新违禁词 RAG 的闭环流程是什么？

四类热数据：
  ① 内容表现数据（TikTok 后台直接给）
     → 完播率、均观时长、点赞、评论、分享、涨粉
  ② 评论区语义数据
     → 用户在说什么词、什么情绪、什么疑问
  ③ 平台规则变化数据（TikTok 社区规范更新日志）
     → 规则变了你不知道，等于蒙着眼睛开车
  ④ 竞品/同行信号数据
     → 同品类、同矩阵打法的账号，免费的风控警报器

PM 选择：
  最紧急的是 ③ 平台规则变化数据。


【第 4 轮】平台规则监控方案 —— 从人肉到自动化
----------------------------------------------------------------
风控审核员追问：
  你具体怎么盯？每周看一次官方文档？

  三个问题暴露"人肉单点故障"：
    1. 每次看什么？靠人脑记忆判断"跟上周不一样"？
    2. 发现了变化然后呢？怎么判断对你 405 条/天流水线的影响？
    3. 你请假了怎么办？流程绑在你一个人身上。

PM 反思：不清楚。

风控审核员方案 —— 三人三层监控链：
  第一层（机器）：changedetection.io 每 24h 截图对比 TikTok 社区
    规范页面，有变化自动 webhook 通知 → 零代码，10 分钟配完。
  第二层（AI）：DeepSeek 比对旧版新版，自动输出：
    ① 影响对象 ② 风险等级（高/中/低） ③ 怎么改。
  第三层（人）：PM 扫 AI 标了"高风险"的条目，做最终决策。
    不再是整个流程的引擎，只是最后一环。

PM 确认：
  这是一个工程级的项目，越来越像一个可以落地的项目了。


【第 5 轮】违禁词 RAG 三层定位 + 信号采集层
----------------------------------------------------------------
回到未解决的违禁词 RAG 三个问题：

  PM 决策：
    挂在哪一层 → 翻译层（Phase 2 翻译通道输出点）
    怎么匹配   → 语义匹配（TikTok 用语义算法审内容，
                 精确词库挡不住语境性违规）
    怎么更新   → 不清楚

风控审核员追问"怎么更新"四个子问题：
  1. 谁负责更新？→ PM 决策：LLM 自己更新，飞轮才能转
  2. 违禁信号从哪来？→ TikTok 不给精确诊断

风控审核员分析 TikTok 四级处罚信号：
  ① 视频级：shadow ban + 违规大类标签（分钟级，代价最低）
  ② 账号级：警告 → 功能限制 → 限时封号 → 永久封禁（逐级上报）
  ③ 同行级：竞品账号被封（零代价，延迟天级）
  ④ 社区规范更新级：规则页面变化（提前预警，不依赖惩罚）

PM 选择：
  最先接视频级 shadow ban + 违规大类标签。

  架构确定：
    信号采集层 → LLM 识别推断嫌疑词 → 违禁词 RAG 自动更新
    → 翻译后安全扫描 → 分发前熔断


【第 6 轮】置信度分层拦截 —— 全自动 vs 人工审核的边界
----------------------------------------------------------------
风控审核员追问：
  LLM 推断嫌疑人词时猜错了怎么办？
  好词被误标违禁 → 同类型内容全被误杀。

PM 最终决策（零容忍分界线）：

  永久封禁级（仇恨言论/政治禁忌）
    → 置信度 < 100% → 强制人工审核，零容忍
      置信度 = 100% → 自动拦截

  功能限制级（商业违规/版权）
    → 置信度 ≥ 90% → 自动拦截
      置信度 < 90% → 人工审核

  内容限流级（低质/重复内容）
    → 置信度 ≥ 70% → 自动拦截
      置信度 < 70% → 标记放行 + 后续监控


================================================================
三、第三阶段核心结论
================================================================

1. 违禁词 RAG 挂翻译层（Phase 2 输出点），语义匹配，与 TikTok
   审核逻辑一致

2. 信号采集层是违禁词 RAG 的前置依赖 —— 没有信号，LLM 无法
   自动更新，飞轮转不起来

3. 最先接视频级信号（shadow ban + 违规大类标签）：
   速度最快、代价最低、信息最精确

4. LLM 自己维护违禁词 RAG，实现自动闭环：
   信号采集 → LLM 推断 → RAG 更新 → 安全扫描 → 分发熔断

5. 按处罚等级分层设置 LLM 置信度阈值：
   永久封禁级零容忍（<100% 必须人工）→ 功能限制级（90%）
   → 内容限流级（70%）→ 逐级降低人工介入频率

6. 社区规范监控三层链兜底：
   changedetection（机器）→ LLM 拆解（AI）→ PM 决策（人）

7. 飞轮闭环已拉通，误杀率可通过数据迭代调整各层阈值

附：推演方法论
================================================================

本次推演采用"风控审核员极度愤怒的小白用户"角色扮演方法：
  - 先设定一个极端的业务灾难场景（45 个号全部永封）
  - 逐层追问 PM 的应对方案
  - 每次 PM 给出方向后，用反面逻辑攻击方案的盲区
  - 如果方向被击穿 → 暴露盲区，深挖到更底层
  - 最终找到"可以在工程层面落地实现的完整闭环"

本次与前两个阶段的关联：
  - 第一阶段锁定了"适应平台 + 内容质量"的商业方向
  - 第二阶段锁定了"RAG + metadata filter"的技术架构
  - 第三阶段在第二阶段的技术架构上增加了 Layer 0（安全合规天幕），
    补齐了整个系统最大的盲区：内容安全审核的自动化闭环
